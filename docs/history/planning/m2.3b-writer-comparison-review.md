## Spending and execution controls

**Proposed ceilings, not spending authorization:** GPT0.20USD, Sonnet0.20USD,
Llama0.10USD; aggregate0.50USD. At a **separately verified** input bound of32,768
provider tokens plus2,048 output tokens, standard-rate reservations would be
GPT0.112640USD and Sonnet0.129024USD. Llama remains unpriced; no three-model live
run can proceed. These are conditional upper-bound calculations, not a new token
measurement or a claim of expected cost. All ceilings can be lowered in approval;
expansion requires a reviewed configuration change.

Before parallel dispatch, a single locked ledger validates and reserves **all**
selected requests. It checks configuration/logical/request hashes, current rates,
per-model and aggregate ceilings, explicit source-sharing/model-access confirmations,
model-specific token-bound evidence and separate owner authorization. Missing or
unresolved information blocks the whole selection before output creation or transport.
One claim per selected model; maximum3 requests. No automatic retry, fallback,
repair or regeneration. Failed/unknown billing keeps the complete reservation;
known estimates do not free budget to make more calls. Another thread cannot reserve
or claim the same run/model twice. An exclusively created, fixed protected output
directory prevents cross-process reruns, including after a crash or failure.

A token-bound reference is an explicit **owner/operator qualification record**, not
an automatic tokenizer or cryptographic proof. We have not measured GPT/Claude/Llama
input tokens. Do not fill in a guessed number or reuse Qwen's7,052 count. Obtain
credible provider-specific counts/bounds for the exact request before authorizing.
The local ceilings depend on valid qualification and rates; they are not provider
invoice limits or a guarantee against provider billing errors. Unexpected usage,
reasoning, cache-write charges or missing counters are retained as failures with
unknown billing; no draft is admitted. Cached input is estimated at full list rate,
so reported costs are conservative usage-based estimates, not invoices.
