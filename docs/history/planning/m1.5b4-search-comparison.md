## Result and recommendation

| Method | Cases meeting all expected-claim top-three checks | New passing cases versus semantic | Lost passing cases |
|---|---:|---|---|
| Semantic E5 | 7/8 | Baseline | None |
| BM25 keyword | 6/8 | None | India evidence-gap case GTM-08 |
| Equal-weight RRF hybrid | 7/8 | None | None |

Keyword search did help the missing flavor claim's rank: semantic6 -> keyword4.
Hybrid placed it5. Neither put it within the required top three. Keyword also moved
the inspiration claim from semantic2 to keyword6. Hybrid retained inspiration3.

Hybrid improved some individual positions: variants2 ->1 and India unknowns2 ->1,
while tying the semantic pass count. It did not close the flavor/inspiration miss.
The predeclared adoption rule required more passing cases without losing any
previously passing case; hybrid did not meet that rule.

**Recommend retaining semantic retrieval with bounded declared-claim reference
follow-up for the frozen MVP.** The earlier independent follow-up already recovered
PROD-002 with full source support. No more retrieval parameter tuning is recommended
now; next implementation scope should integrate this evidence-completion behavior
into the retrieval tool and verify it before the autonomous GTM experience.

This is not proof that keyword or hybrid search never helps. It compares one fixed
BM25 analysis and one equal-weight fusion configuration on eight selected cases.
We preserve improvements, regressions and misses rather than declaring any method
universally superior. No new runtime retrieval strategy was installed or adopted.

## Fair comparison setup

- Same original queries, expected units, top-three criterion, product/authority
  filters, approved45-record corpus and focused embedding_text for both branches.
- BM25 scored locally: lowercase alphanumeric tokens, no stopword removal, stemming
  or synonyms; unique query terms; k1=1.2,b=0.75,positive Lucene-style IDF. Statistics
  used the eligible authority-filtered corpus. Zero-score documents were excluded.
- Hybrid summed reciprocal ranks,1/(60+rank), with equal semantic/keyword weights.
  Chunk ID resolved exact score ties deterministically. No expected-answer IDs or
  claim-link expansion affected any ranking.
- Both branches used all eligible candidates (30 public-fact or15 synthetic-intent
  records). Pinecone topK was expanded to that candidate count so fusion could
  consider the missing claim, rather than fusing only the old top five. The pass
  cutoff remained3, not expanded. All eight current semantic top-five lists exactly
  reproduced the original hosted baseline, despite the deeper candidate retrieval.
- Parameters and decision rule were saved in tools/gtm_search_comparison_profile.json
  before any candidate rankings were inspected. No retuning, query rewriting,
  fallback configuration or post-result criterion changes.

The small Python BM25/fusion implementations are independent experimental code;
Lucene/Elasticsearch were not installed. Parameter/formula references:
[BM25 defaults and IDF](https://lucene.apache.org/core/9_12_2/core/org/apache/lucene/search/similarities/BM25Similarity.html),
[reciprocal rank fusion](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion).
