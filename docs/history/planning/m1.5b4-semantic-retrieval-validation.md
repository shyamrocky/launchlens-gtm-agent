## Plain-English finding

Semantic search now has an observed baseline. Seven checks found every expected
supporting unit in the top three. The combined flavor/inspiration query found a
relevant overview first and the inspiration claim second, but did not directly
retrieve the dedicated cherry/vanilla claim PROD-002 in its top five. We preserve
that miss rather than changing expectations after seeing results.

The overview itself describes cherry/vanilla and soda-float inspiration and already
links to the exact PROD-002 and PROD-003 chunk IDs. Thus this is a direct claim-level
coverage gap, not a finding that the returned overview is irrelevant or that the
underlying flavor evidence is missing from storage. Following those existing links
is a candidate small remedy; it was not executed or implemented here.

## Fixed method and scope

Eight component research queries were fixed in tools/gtm_retrieval_cases.json before
hosted execution. They support a GTM package, not a general nutrition-Q&A product.
Each used topK=5; all expected units must occur within ranks 1-3 to pass. No expected
IDs were put in query text or filters. Explicit filters used only product ID and the
case's preselected authority. This validates filtering as supplied, not an agent's
autonomous selection of the right domain or research questions.

Existing index launchlens-e5-sample-v1, namespace m15b4-corpus-validation-v1. All
records compete within the selected authority (30 public-fact or 15 synthetic-intent
records). One multilingual-e5-large query-embedding batch, input_type=query and
truncate=NONE, with no manually duplicated query prefix. No reranker, keyword
search, query rewrite, fallback, retries or post-result threshold changes.
