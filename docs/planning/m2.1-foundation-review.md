## What now works

One registered task: Coca-Cola Cherry Float - GTM Package Preparation. Markets
US/UK/IN; explicit valid evaluation date; one supported objective, flavor_discovery:
“Introduce Cherry Float's flavor and classic soda-float inspiration”. Registry data
is maintained configuration and returned as a fresh copy, not a model interpretation,
Notion job queue or mutable product database. Source IDs/host/namespace reuse existing
accepted tool constants. Extra/missing fields and unsupported selections fail before
model/tool execution; an invalid replacement preserves the current valid task.

The actual LangGraph graph is decide -> dispatch -> decide, with conditional end
or clarification interrupt/resume. Model and tool adapters are scripted/safe fixtures.
Different research orders pass the same completion prerequisites. Python owns
admission, authoritative state, scope, budgets and terminal outcomes. A model returns
one validated action, not a state patch; its view and returned snapshots are copies.

Allowed model actions: read_pmm_brief, check_launch, search_product_evidence,
request_clarification, finish. Scope arguments are bound from the validated request;
model-provided market/date/approval arguments are rejected. Launch decisions use
unchanged evaluate_launch on operational fixture records; forged top-level verdicts
and malicious narrative cannot override them. Source authority/digests/bindings and
record completeness are checked; duplicates and contradictory flags are rejected.
Synthetic intent or an incomplete claim cannot substitute for a usable public claim.
A partial extra summary remains labeled partial when another complete claim is usable.

Research completion requires PMM, a permitting launch decision and usable public
product-claim evidence. This is structural preparation, not proof of semantic
relevance, copy quality, complete corpus coverage or eventual marketing readiness.
No draft or Reviewer is implemented. Empty draft/review/acceptance slots reserve
state ownership and allow cleanup tests; they do not represent functional generation.

## One current package and replay/reset behavior

- Generate again validates first, removes old task/checkpoints and starts a fresh
  unique run with empty evidence, ledger, feedback, draft/review and acceptance.
- Reset removes current in-memory state/checkpoints and leaves no active task.
  No source/provider write, trace deletion or exported-file deletion occurs.
- Old run IDs cannot run/resume; no draft archive or historical run browser.
- Resume uses a real LangGraph Command against its saved interrupt/thread. It
  preserves counters and ledger; plain feedback cannot grant operational permission.
- Re-running a completed/paused run without explicit resume returns its state,
  without model/tool calls. Completed action IDs replay recorded results; changed
  arguments or uncertain pending actions stop safely instead of invoking again.
- Replacement/reset/concurrent execution are rejected while running. No background
  cancellation, persistence across restarts or crash-proof exactly-once guarantee.
- Model-facing actions cannot reset the task/budgets or set review/acceptance.

## Dependency preservation finding and resolution

Initial root installation of LangGraph caused legacy chunk/projection validation to
reject changed pyproject.toml: the accepted page manifest hashes the original root
metadata/lock. Reported regression failures were real. They were resolved by restoring
the exact original root metadata/lock and root environment, not weakening hashes,
editing old validators, changing historical bindings or regenerating evidence.

The foundation now has an explicit isolated tools/agent_foundation profile, following
the existing embedding-preparation convention. LangGraph1.2.20, checkpoint4.3.1,
langchain-core1.7.6 and LangSmith0.14.17 are locked. LangSmith is already transitive;
it is explicitly pinned because tracing_context is imported to disable transmission.
The separate full langchain package is not installed. Pydantic is a transitive
framework dependency, not a new authored schema framework. Original pypdf6.21.4,
root pyproject/lock, isolated embedding profile, sources and generated artifacts remain
byte unchanged. This new dependency profile is implemented pending owner review.

## Provisioning and reproduction

Python3.12, uv; no system-wide installation or service credentials. Required runtime
packages are provisioned explicitly outside workspace:

```sh
uv sync --project tools/agent_foundation --locked --python 3.12 --no-python-downloads
tools/agent_foundation/.venv/bin/python tools/demo_agent_foundation.py
tools/agent_foundation/.venv/bin/python -m unittest discover -s tools/agent_foundation/tests -q
```

Use this profile's interpreter for modules that require LangGraph; the frozen root
profile intentionally does not contain it. Runtime application imports require src
on PYTHONPATH or an approved entrypoint; the maintained demo sets its own source
path and runs from any cwd. Its fixtures are explicit simulated inputs, never a
silent fallback for live tools. No runtime file/credential/generated/workspace reads.

Existing regressions:

```sh
.venv/bin/python -m unittest discover -s tests -q
tools/embedding_preparation/.venv/bin/python -m unittest discover -s tools/embedding_preparation/tests -q
```
