## Responsibilities and contracts

**Model:** chooses whether to research, draft, request critique, revise or stop via
registered actions. The offline demonstration uses scripted choices to test wiring.
A fixed script is not represented as observed live autonomous behavior.

**Harness:** owns task/launch eligibility, exact draft and review identities, action
execution/replay, total turn budget, one original writing attempt, at most two
reviews and one revision attempt. Review is mandatory before human handoff. After
review, it stops at `awaiting_human_review`; it never revises automatically.

`request_revision(run_id, feedback, draft_version=..., draft_sha256=...)` is an
owner-only application command, absent from the model action registry. It validates
the exact current reviewed version, queues permission and makes no provider call.
Only a subsequent permitted model action can execute the revision. Changed drafts
clear current review, remain human-unaccepted and require fresh version-bound review.
The revised review receives the original findings and owner feedback as context,
not as evidence or an inherited verdict. Failure/unresolved findings cannot cause
another retry, repair or revision. Reset/new run clears these session controls.

The Reviewer receives exact draft/task, original Writer instructions, evidence with
citations/qualifications, PMM guidance, launch constraints, editorial warnings and
material caveats/conflicts. The optional accepted projection retains full backend
authority. Review output contains six assessments (grounding, qualifications, voice,
tone, consistency, completeness) and actionable findings: exact field/quote, severity,
rationale, suggested change and eligible claim IDs. A non-pass assessment requires a
blocking finding. Uncertainty remains explicit. Advisory word counts are not hard
failures. An unsupported or nonfactual critique may have no supporting claim IDs;
this is a Reviewer finding, not a Writer citation entry. **The Writer's prohibition
on empty citation arrays is unchanged.**

The harness validates review structure, quotation occurrence, assessment consistency
and eligible IDs; these checks do not establish semantic entailment. A model can
still return a structurally valid but mistaken clean assessment. This limitation
is tested explicitly. No review grants human approval or publishing permission.
