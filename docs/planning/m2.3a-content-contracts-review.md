## Readable contract overview

All templates describe internal, human-reviewable drafts and leave the agent free
to choose its angle and wording. The campaign brief anchors creative direction;
public factual support still comes from retrieved Product Brief evidence and launch
permissions still come from the existing Notion/harness checks.

| Template / model format | Required content fields | Editorial defaults, advisory only |
|---|---|---|
| [Campaign Brief](../../data/templates/gtm/campaign_brief.json) / campaign_brief | objective; audience_hypothesis; positioning; exactly three messaging_pillars; nonempty tone list; primary_cta; restrictions_and_unknowns list | 250–400 words; synthesize PMM guidance; identify hypotheses and unresolved constraints |
| [LinkedIn](../../data/templates/gtm/linkedin_post.json) / linkedin | hook; body; cta; hashtags list | 100–180 words across hook/body/CTA; approximately three relevant hashtags; informative, accessible professional tone |
| [Email](../../data/templates/gtm/promotional_email.json) / email | subject; preview_text; headline; body; cta | Body 100–160 words; subject at most 60 characters/nine words; preview 40–90 characters; preview complements subject |
| [Blog](../../data/templates/gtm/short_blog.json) / blog | title; introduction; at least one section with heading/body; conclusion; cta | 300–450 words; prefer two or three useful sections; no filler to reach a target |
| [Ad variations](../../data/templates/gtm/ad_variations.json) / ads | exactly three concepts, each with angle; headline; body; cta | Per concept: headline at most 60 characters, body 125, CTA 25; distinct creative angles; platform-neutral concepts |

Missing/blank required text, wrong types, extra fields and wrong hard array counts
raise ContractError. List fields such as hashtags and restrictions_and_unknowns may
be empty. Length/hashtag/section targets yield advisory findings and never alone
reject a structurally complete draft. Word counts use whitespace-separated words;
character counts include spaces; these are not model tokens or platform compliance
checks. Distinct ad meaning is a Reviewer criterion, not proved by having three rows.

## One shared model envelope

[content_contracts.py](../../src/launchlens/content_contracts.py) provides the common
version-1 contract and review criteria for all formats. Example structure below is
an independently authored structural fixture, not generated marketing content:

```json
{
  "format": "linkedin",
  "content": {
    "hook": "SAFE FIXTURE hook",
    "body": "SAFE FIXTURE passage requiring evidence",
    "cta": "SAFE FIXTURE informational invitation",
    "hashtags": []
  },
  "claim_references": [
    {"content_field": "body", "claim_ids": ["PROD-002"]}
  ]
}
```

Field paths are relative to content: body, messaging_pillars.0, sections.0.body,
concepts.1.headline. Each reference must identify an existing string field, and
claim_ids must be a nonempty unique list. One entry per field may list several
supporting claims. References are review metadata, not inline additions to the
rendered copy. An empty reference list is structurally allowed for purely creative
text; identifying all factual assertions and rejecting unsupported prose remains
required semantic review.

Claim IDs must resolve to complete retrieved public-product-claim records supplied
by the caller. The validator reuses the existing evidence codec and frozen source
checks: product/document/version/source-acceptance binding, unit identity, digest,
claim mappings and reference completeness. Unretrieved IDs, synthetic PRD evidence,
partial evidence and corrupted records cannot validate a factual reference. URLs,
qualifications and provenance remain in those original evidence packets; the model
does not create a replacement evidence source.

Draft version, run identity, review findings/status, human acceptance and launch
permissions stay application-owned, outside this model envelope. Such extra fields
are rejected at both outer and content levels. This checkpoint defines the boundary;
it does not implement a draft store or review/approval state machine.

## CTA and factual safety: explicit requirements, future semantic enforcement

The shared review criteria explicitly forbid invented discounts, purchase
locations/URLs, offers, stock, availability dates and performance claims. A purchase
or offer CTA requires evidence of its terms and an authorized destination; a public
announcement is insufficient. Without a provided destination, an informational or
engagement CTA must not fabricate a link. Audiences and proposed positioning remain
hypotheses; ordinary imaginative language is not automatically a factual claim.

**Structural validation is not a marketing safety verdict.** A string containing
an unsupported offer can fit the schema. The tests deliberately demonstrate that
it still requires semantic review; even an eligible PROD ID cannot substantiate
unrelated wording. No discount detection, URL authorization service or semantic
entailment classifier has been invented for M2.3a. M2.3b must wire actual launch and
CTA/evidence constraints into draft admission; M2.3c must critique factual support,
qualifications, CTA legitimacy, tone and consistency and require bounded correction.
No draft may be presented as reviewed or approved based on this validator alone.

## Configuration and reproduction

The five JSON files are version-controlled application configuration, not evidence
or generated datasets. They are directly loaded by an allowlisted format/file map;
no Pinecone embeddings, semantic template search or new dependencies. Each has
version1.0, content_schema, editorial guidance, review criteria and a shared-contract
identifier. The schemas use a small standard keyword subset; the Python validator
implements only that subset and is not advertised as a general JSON Schema engine.
Unsupported schema keywords and unknown formats fail explicitly.

Canonical setup is a repository checkout containing src/launchlens and
 data/templates/gtm. The loader resolves the template directory relative to its
source location, not cwd, .env, generated data or workspace. Missing configuration
fails without an ignored-file fallback. Future packaging must provision these same
canonical files; no package/deployment infrastructure was added here.

Public entry points:

- load_template(format_name): fresh copy of the format configuration.
- model_output_schema(format_name): shared strict envelope plus content shape.
- COMMON_REVIEW_CRITERIA: common evidence/CTA/authority/review instructions; future
  generation/review adapters must include these alongside channel-specific guidance.
- validate_draft(draft, format_name=..., evidence_records=...): structural/reference
  checks and advisory findings; returns semantic_review_required=true, never approval.
